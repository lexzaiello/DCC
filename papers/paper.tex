\section{Background}

\subsection{The Untyped Categorical Combinators}

The categorical combinators \autocite{CURIEN1986188} are the basis of the Categorical Abstract Machine \autocite{cmachine}. As shown by Cousineau et al., they are a potential compilation target for the \(\lambda\)-calculus. Categorical combinators simulate variable substitution with projection over nested tuples (``couples'') constituting the ``environment'' and a curry combinator (\(\Lambda\)). The reduction rules for this calculus resemble the rules of the SK combinator calculus, and their categorical semantics are given by cartesian-closed categories \autocite[p. 178]{cmachine}.

\begin{figure}[h!]
\begin{center}
\begin{tabular}{l l}\label{red_untyped_cat}
(ass) & \((x \circ y) z = x(y z)\) \\
(fst) & \(Fst(a, b) = a\) \\
(snd) & \(Snd(a, b) = b\) \\
(dpair) & \(\langle x, y\rangle z = (x z, y z)\) \\
(curr) & \(\Lambda(x)yz = x(y, z)\) \\
(app) & \(App(f, x) = f x\) \\
(quote) & \(`(x) y = x\)
\end{tabular}
\end{center}

\end{figure}

\section{Dependent Categorical Combinators}

Our primary insights when extending the categorical combinators to dependent types are: when typed as \(\Sigma\)-pairs, couples can naturally encode contexts and typing judgments; pairs which produce couples correspond to substitution within contexts; the types of all primitive objects can be represented without the pair rule (the affine restriction) after adding a \(Flip\) combinator. By showing that the affine restriction is strongly normalizing, we gain decidable judgmental equality (\(\equiv\)) and a decision procedure for type-checking.

As usual, we extend the calculus with a \(\Pi(m, n)\) object. Arrows \(\alpha \rightarrow \beta\) are represented by \(\Pi\) objects that quote their codomain. We re-interpret the base combinators as pertaining to \(\Sigma\) couples, instead of product couples. 

\subsection{Couples as Dependent Sums}

We interpret couples \((a, b)\) as \(\Sigma\)-pairs like such:

\begin{center}\label{coup_exp}
\begin{figure}[h!]\label{coup_dep}
\centering
\begin{tabular}{c}
  \inferrule[\(\text{Coup}_{1}\)]
  { \Gamma \vdash \alpha : \sort{m}, \beta : \alpha \rightarrow \sort{n}\\ \Gamma \vdash x : \alpha, y : \beta x}
  {\Gamma \vdash \llbracket \alpha, \beta \rrbracket (a, b) : \Sigma(\alpha, \beta)}
\end{tabular}
\caption{Couples as dependent sums}
\end{figure}
\end{center}

We require that \(\beta : \alpha \rightarrow \sort{m}\) be given explicitly in couples through the type annotation \(\llbracket \alpha, \beta \rrbracket\). Similarly, we add type arguments to pairs (\(\llbracket \beta, \gamma\rrbracket \langle f, g\rangle\)) which allow the resulting couple's \(snd\) component to depend on the term \(f x\). Pairs are not point-free, but couples are (with respect to \(x\) and \(y\)), since the categorical combinator \(\Lambda(\ldots)\) can simulate a binder, but its type (and other combinators' types) must be bootstrapped with point-free couples. The point-free type of \(\llbracket \alpha, \beta \rrbracket (,)\) is available in the appendix.

This view of couples as sigma terms naturally encodes the notion of judgments. For example, the term \(\llbracket \sort{m}, Id(\sort{m})\rrbracket (\alpha, x)\) corresponds to the judgment \(x : \alpha\). Similarly, a context \(\Gamma\) can be encoded as a nested couple:

\begin{equation}
  x_0 : A_0, x_1 : A_1(x_0), x_2 : A_2 (x_0, x_1) \approx
  \llbracket \Sigma(A_0, A_1), A_2 \rrbracket (\llbracket A_0, A_1 \rrbracket (x_0, x_1), x_2)
\end{equation}

In the categorical abstract machine, this encoding of judgments corresponds to an environment where variable assignments are explicitly typed.

\subsection{Type Annotations as Points via Couple-Judgments}

Except for \(\Pi\), all combinator objects have type annotations specified as points. For example, the projection \(Fst(\alpha, \beta)\) is indexed by terms denoting the type of the expected \(\Sigma\)-couple. This contradicts intuition that type arguments must be able to depend on other terms, and thus, cannot be points. However, by referring to terms in the context as the \(snd\) component of a \(\Sigma\)-couple (\(\Sigma(\sort{m}, Id(\sort{m}))\)) mentioning its type, they only need to be referred to by their respective sorts. As a result, we avoid another potential duplication of type-points inside the combinators' types. \(\Sigma\)-judgments are also an example of ``very dependent'' types, as defined by Altenkirch et al. \cite{altenkirch}.\\\\
See \eqref{point_free_derivation} where we derive point-free \(Id\ \alpha\) using the dependent curry (\(\Lambda\)) combinator and \(\Sigma\)-judgments.

\subsection{Inference Rules}\label{infer_rules}

We make use of an infinite sort hierarchy to avoid paradoxes (i.e., \(\sort{m} : \sort{m + 1}\)). We also use the notation \(\Pi(x : A), B\), and may omit type arguments for legibility to denote an illustration of a type. However, the full combinatory, point-free types are accessible in the appendix. We use \(A \rightarrow B\) as shorthand for our definition of arrows \eqref{arrow_def}, but arrows are not first-class, and are merely an application of \(\Pi(m, n)\).

\subsubsection{Application and \(\Pi\)}

The inference rule for function application is as usual, except the codomain \(\beta\) is applied the \(\Sigma\)-judgment \(\llbracket \sort{m}, Id(\sort{m}) \rrbracket (\alpha, x)\).

\begin{figure}[h!]
\begin{equation}
  \inferrule[App]
  { \Gamma \vdash f : \Pi(m, n) \alpha \beta\\ \Gamma \vdash x : \alpha}
  { \Gamma \vdash f x : \beta \llbracket \sort{m}, Id(\sort{m}) \rrbracket (\alpha, x)}
\end{equation}
\caption{Inference rule: application}
\end{figure}

Since we do not make use of variables, \(\Pi(m, n)\) is itself a dependent combinator, naively dependently typed \eqref{naive}. However, since we apply function type codomains (\(\beta\)) with \(\llbracket \ldots \rrbracket(\alpha, x)\), it can be expressed as an arrow type \eqref{arrow_pi}. Our use of the judgment-couple convention in the type of \(\Pi(m, n)\) proves to be useful in several other combinator types, avoiding duplication of elements in the context.

\begin{figure}[h]
\begin{equation}\label{naive}
  \Pi(m, n) : \Pi(\alpha : \sort{m}, \beta : \alpha \rightarrow \sort{n}), \sort{n}
\end{equation}
\caption{Naive typing of \(\Pi(m, n)\) with a dependent type}
\end{figure}

\begin{figure}[h]
  \begin{equation}\label{arrow_pi}
    \inferrule
    { }
    {\Gamma \vdash \Pi(m, n) : \sort{m} \rightarrow (\Sigma(\sort{m}, Id(\sort{m})) \rightarrow \sort{n}) \rightarrow \sort{n}}

\subsubsection{Arrow types}

We define nondependent arrows (\(\alpha \rightarrow \beta\)) as such (where \(`(\ldots)\) denotes the quotation combinator of arity 3):

\begin{figure}[h!]
\begin{equation}\label{arrow_def}
  \inferrule
  { \Gamma \vdash \alpha : \sort{m}\\ \Gamma \vdash \beta : \sort{n}}
  {\Gamma \vdash \alpha \rightarrow \beta \coloneq \Pi(m, n)\ \alpha\ `(\sort{n}, \Sigma(\sort{n}, Id(\sort{m})), \beta)}
\end{equation}
\end{figure}

\subsubsection{Couple Projections}

We define dependent and nondependent versions of \(Snd\) projection to bootstrap several of the combinators' types. \(Fst(\alpha, \beta)\) is not dependent, since \(\alpha\) does not depend on \(\beta\) in \(\Sigma(\alpha, \beta)\). We use \(\circ'\) to denote nondependent composition where \(g : \alpha \rightarrow \beta\) and \(f : \beta \rightarrow \alpha\).
The inference rules for projection on couples are as such:\\

\begin{figure}
  \centering
  \begin{tabular}{c c}
    \inferrule[Fst]
    {\Gamma \vdash \alpha : \sort{m}, \beta : \alpha \rightarrow \sort{n}}
    {\Gamma \vdash Fst(\alpha, \beta) : \Sigma(\alpha, \beta) \rightarrow \alpha}&
    \inferrule[Snd']
    {\Gamma \vdash \alpha : \sort{m}, \beta : \alpha \rightarrow \sort{n}}
    {\Gamma \vdash Snd'(\alpha, \beta) : \Sigma(\alpha, \beta) \rightarrow \beta}\\\\
  \end{tabular}
  \inferrule[Snd]
    {\Gamma \vdash \alpha : \sort{m}, \beta : \alpha \rightarrow \sort{n}}
    {\Gamma \vdash Snd(\alpha, \beta) : \Pi(s : \Sigma(\alpha, \beta)), \beta(Snd\ s)}
\end{figure}

\subsubsection{Identity combinator}

As do all other combinators, \(Id\) accepts \(\alpha\) as a point. Its type is a simple arrow:

\begin{equation}
  \inferrule[Id]
  {\Gamma \vdash \alpha : \sort{m}}
  {\Gamma \vdash Id(\alpha) : \alpha \rightarrow \alpha}
\end{equation}

\subsubsection{Flip combinator}

We extend Curien's combinators \autocite{CURIEN1986188} with a \(Flip(x)\) combinator. We do so to avoid copying when applying an argument under \(\Pi(m, n)\) as the domain of a subsequent \(\Pi(n, o) \beta\) object:

\begin{equation}
  \inferrule[Flip]
  { \Gamma \vdash x : \alpha \rightarrow \beta \rightarrow \gamma}
  { \Gamma \vdash Flip(x) : \beta \rightarrow \alpha \rightarrow \gamma}
\end{equation}

\subsubsection{Dependent and nondependent composition}

We have nondependent composition as in Curien's combinators, and add a dependent version. Naively interpreting composition as dependent leads to the \(S\) combinator, so we use our \(\Sigma\)-couples to avoid duplication and preserve dependency.

\begin{equation}
  \inferrule[Naive comp.]
  { \Gamma \vdash f : \Pi(x : \alpha), \beta(x), g : \Pi(x : ?), \gamma (f x)}
  { \Gamma \vdash (g \circ f) : \Pi(x : \alpha), \gamma (f x)}
\end{equation}

Note that the codomain of \(f\) depends on \(x : \alpha\), but the domain of \(g\) also depends on \(f x : \beta(x)\). By duplicating \(x\), \(?\) can be determined:

\begin{figure}[h!]
\begin{equation}
  \inferrule[Naive comp.]
  { \Gamma \vdash f : \Pi(x : \alpha), \beta(x), g : \Pi(x : \alpha, y : \beta(x)), \gamma x (f x)}
  { \Gamma \vdash (g \circ f) : \Pi(x : \alpha), \gamma (f x)}
\end{equation}
\end{figure}

We avoid copying \(x\) altogether by stipulating that \(f\) produce a couple \(\Sigma(\alpha, \beta)\). As such, duplication is handed off to term-level \(\beta\)-reduction, and our types remain affine. We define composition point-free, up to the type arguments \({\alpha, \beta, \gamma}\) \eqref{comp}. The type of the nondependent composition operator is the same as in Curien's simply-typed combinators \autocite[p. 220]{CURIEN1986188} \eqref{nondep_comp}.

\begin{figure}[h!]
  \centering
  \begin{equation}\label{comp}
    \inferrule[Comp.]
    { \Gamma \vdash \alpha : \sort{m}, \beta : \alpha \rightarrow \sort{n}, \gamma : \Sigma(\alpha, \beta) \rightarrow \sort{o}}
    { \Gamma \vdash \llbracket \alpha, \beta, \gamma \rrbracket \circ : \Pi(f : \alpha \rightarrow \Sigma(\alpha, \beta), g : \Pi(x : \Sigma(\alpha, \beta)), \gamma(x), x : \alpha), \gamma(f x)}
  \end{equation}
  \caption{Inference rule: composition in illustrative notation.}
\end{figure}

\begin{figure}[h!]
  \centering
  \begin{equation}\label{nondep_comp}
    \inferrule[Nondep. comp.]
    { \Gamma \vdash f : \alpha \rightarrow \beta, g : \beta \rightarrow \gamma}
    { \Gamma \vdash (g \circ f) : \alpha \rightarrow \gamma}
  \end{equation}
  \caption{Inference rule: nondependent composition}
\end{figure}

\subsubsection{Pairs}

Recall \(\langle f, g \rangle x = (f x, g x)\). We extend the pair operator with type arguments \(\beta\), \(\gamma\), which dictate the types of the resulting \(fst\), and \(snd\) component, respectively. All arguments, up to \(x\), are given by points \eqref{pair_infer}.

\begin{figure}[h!]
  \centering
  \begin{equation}\label{pair_infer}
    \inferrule[Pair]
    { \Gamma \vdash \beta : \sort{n}, \gamma : \beta \rightarrow \sort{o}, f : \alpha \rightarrow \beta, g : \Pi(x : \alpha), \gamma(f x)}
    { \Gamma \vdash \llbracket \beta, \gamma \rrbracket \langle f, g \rangle : \alpha \rightarrow \Sigma(\beta, \gamma)}
  \end{equation}
\end{figure}

\subsubsection{Quotation}

The quotation operator (\(`(\alpha, \beta, x)\)) is not dependent, but a dependent version like the dependent \(K\) combinator can be derived as in our \(Id(m)\) derivation \eqref{point_free_derivation}.

\begin{figure}[h]
  \centering
  \begin{equation}
    \inferrule[Quot]
    { \Gamma \vdash \alpha : \sort{m}, \beta : \sort{n}, x : \alpha}
    { \Gamma \vdash `(\alpha, \beta, x) : \beta \rightarrow \alpha }
  \end{equation}
\end{figure}

\subsubsection{Tail and head-dependent Curry}

Recall \(\Lambda(x) y z = x (y, z)\). Since \(x\) is applied a \(\Sigma\)-couple, \(z\) must depend on \(y\). That is, \(z : \beta(y)\). However, \(x\) also depends on the couple \(\llbracket \alpha, \beta \rrbracket (y, z)\). To keep usages of \(y\) and \(z\) affine, we define two versions of \(\Lambda(x)\). The former, \(\Lambda'(\alpha, \beta, x)\) is ``head-dependent'', in that \(z\) may depend on \(y\), but \(x\) has a fixed codomain \eqref{head_curry}. The latter, \(\Lambda(\alpha, x)\) is ``tail-dependent'', in that \(y\) is itself a sort, z is an inhabitant of \(y\), and \(x\) depends on \(\llbracket \alpha, Id(\alpha) \rrbracket (y, z)\) \eqref{tail_curry}.

\begin{figure}[h!]
\begin{equation}\label{head_curry}
  \inferrule[Head Curry]
  {\Gamma \vdash \alpha : \sort{m}, \beta : \alpha \rightarrow \sort{n}, x : \Sigma(\alpha, \beta) \rightarrow \gamma}
  {\Gamma \vdash \Lambda'(\alpha, \beta, x) : \Pi(x : \alpha, y : \beta(x)), \gamma}
\end{equation}
\caption{Inference rule: head-dependent curry}
\end{figure}

\begin{figure}[h!]
\begin{equation}\label{tail_curry}
  \inferrule[Tail Curry]
  {\Gamma \vdash \alpha : \sort{m + 1}, x : \Pi(s : \Sigma(\alpha, Id(\alpha))), \gamma(s)}
  {\Gamma \vdash \Lambda(\alpha, x) : \Pi(x : \alpha, y : x), \gamma \llbracket \alpha, Id(\alpha) \rrbracket (x, y)}
\end{equation}
\caption{Inference rule: tail-dependent curry}
\end{figure}

\subsection{Affine Strong Normalization}

% Link back later: Furthermore, none of our inference rules require referring to \textit{dpair}.

Note that, excluding our \textit{dpair} rule, each single-step combinator reduction uses each of its arguments at most once. That is, this restriction of single-step reduction is affine. Except for congruence, each rule decreases the number of combinators (we  do not consider the couple \(\llbracket \alpha, \beta \rrbracket (,)\) to be a combinator). We thus define a syntactic measure of term size on objects in our calculus, and show that it decreases under affine reduction (\(\dashrightarrow\)) to show that the affine reduction is strongly normalizing.

Formally, we define affine reduction (\(\dashrightarrow\)) as such:

\begin{leancode}
inductive RedAff : Expr → Expr → Prop
  | app      : RedAff (DCC (App(_n, _δ, _τ) ⟦α, β⟧(f, x))) (DCC (f x))
  | fst      : RedAff (DCC (Fst(_δ, _τ) ⟦α, β⟧(a, b))) a
  | snd      : RedAff (DCC (Snd(_δ, _τ) ⟦α, β⟧(a, b))) b
  | snd'     : RedAff (DCC (Snd'(_δ, _τ) ⟦α, β⟧(a, b))) b
  | flip     : RedAff (DCC (Flip(e) x y)) (DCC (e y x))
  | id       : RedAff (DCC (Id(_α) x)) x
  | quot     : RedAff (DCC (`(_α, _β, x) y)) x
  | comp     : RedAff (DCC ((⟦α, β, γ⟧∘ x y) z)) (DCC (x (y z)))
  | comp'    : RedAff (DCC ((x ∘' y) z)) (DCC (x (y z)))
  | curr     : RedAff (DCC (Λ(α, x) y z)) (DCC (x ⟦α, Id(α)⟧(y, z)))
  | curr'    : RedAff (DCC (Λ'(α, β, x) y z)) (DCC (x ⟦α, β⟧(y, z)))
  | congrFun : RedAff f f' → RedAff (DCC (f x)) (DCC (f' x))
  | congrArg : RedAff x x' → RedAff (DCC (f x)) (DCC (f x'))
\end{leancode}

We define the size of all reducible combinators to be the successor of the sum of the sizes of the combinators' constituent term points. For example, \(Id(\alpha)\) has size \(1\), since its point is a term-type, not a term with computational relevance. Irreducible terms are assigned a size of \(0\)~\eqref{fig:size}. We also define a computable \mintinline{lean}{size (e : Expr) : ((n : ℕ) × (PLift (Size e n)))} function which produces a proof of \mintinline{lean}{Size e n}, thus gaining soundness by default (definition omitted, see appendix).

\end{theorem}

\subsection{Affine Global Confluence}

We define the transitive (\(\dashrightarrow^{+}\)) and reflexive transitive closure (\(\dashrightarrow^{*}\)) like such:

\begin{leancode}
def RedAffTrans     := Relation.TransGen RedAff
def RedAffReflTrans := Relation.ReflTransGen RedAff
\end{leancode}

\begin{theorem}
  For all \(A \in Expr\), \(A\) is confluent under \(\dashrightarrow\).
\end{theorem}

\begin{proof}
  We proceed by induction and case analysis on \(\dashrightarrow\). Cases have been omitted for brevity. Consult the appendix.
  \begin{leancode}
theorem RedAff.conf (h₁ : RedAff A B) (h₂ : RedAff A C) :
  ∃ D, RedAffReflTrans B D ∧ RedAffReflTrans C D := by
  induction h₁ generalizing C with
  | comp =>
    cases h₂ with
    | comp => exact ⟨_, .refl, .refl⟩
    | congrFun h =>
      cases h with
      | congrFun h =>
        cases h with
        | congrFun h => cases h
        | congrArg h => exact ⟨_, .single (.congrFun h), .single .comp⟩
      | congrArg h => exact ⟨_, .single (.congrArg (.congrFun h)), .single .comp⟩
      | congrArg h =>
        exact ⟨_, .single (.congrArg (.congrArg (by assumption))), .single .comp⟩
  | congrFun h_r ih =>
    cases h₂
    case comp' | quot | id | app | fst | snd | snd' => cases h_r
    case flip =>
      cases h_r with
      | congrFun h => cases h
      | congrArg h => exact ⟨_, .single .flip, .single (.congrArg h)⟩
    case comp =>
      cases h_r with
      | congrFun h =>
        cases h with
        | congrFun h => cases h
        | congrArg h => exact ⟨_, .single .comp, .congrFun (.single h)⟩
      | congrArg h => exact ⟨_, .single .comp, .congrArg (.congrFun (.single h))⟩
    case curr =>
      cases h_r with
      | congrFun h => cases h
      | congrArg h => exact ⟨_, .single .curr, .single (.congrArg (.sigl (by assumption)))⟩
    case curr' =>
      cases h_r with
      | congrFun h => cases h
      | congrArg h => exact ⟨_, .single .curr', .single (.congrArg (.sigl (by assumption)))⟩
    case congrFun f f' x f'' h =>
      have ⟨_, h₁, h₂⟩ := ih h
      exact ⟨_, .congrFun h₁, .congrFun h₂⟩
    case congrArg f f' x x'' h_x =>
      exact ⟨_, .congrArg (.single h_x), .congrFun (.single h_r)⟩
  | _ =>
    -- remaining cases omitted
    sorry
  \end{leancode}
\end{proof}

\begin{theorem}
  For all \(A \in Expr\), \(A\) is confluent under \(\dashrightarrow^{*}\).
\end{theorem}

\begin{proof}
  We proceed by induction on the well-founded relation \(\dashrightarrow\) \eqref{wellfounded}.
  \begin{leancode}
theorem RedAffReflTrans.conf (h₁ : RedAffReflTrans A B) (h₂ : RedAffReflTrans A C) :
  ∃ D, RedAffReflTrans B D ∧ RedAffReflTrans C D := by
  induction A using instWellFounded.induction generalizing B C with
  | h _ ih =>
    match h₁.cases_head, h₂.cases_head with
    | .inr ⟨_, hra, hrc⟩, .inr ⟨_, hra', hrc'⟩ =>
      have ⟨_, c₁', c₂'⟩ := hra.conf hra'
      have ⟨_, hrB, hrB'⟩ := ih _ hra hrc c₁'
      have ⟨_, hrC, hrC'⟩ := ih _ hra' hrc' c₂'
      have ⟨_, h₁, h₂⟩ := ih _ hra (c₁'.trans hrB') (c₁'.trans hrC')
      exact ⟨_, .trans hrB h₁, .trans hrC h₂⟩
    | .inl heq₁, .inl heq₂ =>
      rw [← heq₁, ← heq₂]
      exact ⟨_, .refl, .refl⟩
    | .inl heq₁, .inr _ =>
      rw [← heq₁]
      exact ⟨_, h₂, .refl⟩
    | .inr _, .inl heq₁ =>
      rw [← heq₁]
      exact ⟨_, .refl, h₁⟩
  \end{leancode}
\end{proof}

\begin{theorem}
  For all \(A \in Expr\), if \(A \dashrightarrow B\) and \(A \dashrightarrow C\), and \(B\) and \(C\) are normal forms, then \(B = C\).
\end{theorem}

\begin{proof}
  We define normal forms as such:
\begin{leancode}
def IsNormAff (e : Expr) : Prop := ¬ ∃ e', RedAff e e'
\end{leancode}
  We proceed by induction on the common reduct of \(B\) and \(C\):

\begin{leancode}
theorem RedAff.norm_unique (h₁ : RedAff A B) (h_norm : B.IsNormAff)
  (h₂ : RedAff A C) (h_norm₂ : C.IsNormAff) : B = C := by
  have ⟨D, ha, hb⟩ := h₁.conf h₂
  match ha.cases_head, hb.cases_head with
  | .inl h₁, .inl h₂ =>
    simp_all
  | .inr ⟨c₁, h₁, h₂⟩, _ =>
    exact h_norm.elim ⟨_, h₁⟩
  | _, .inr ⟨c₁, h₁, h₂⟩ =>
    exact h_norm₂.elim ⟨_, h₁⟩
\end{leancode}
\end{proof}

\begin{theorem}
  For all \(A \in Expr\), if \(A \dashrightarrow^{*} B\) and \(A \dashrightarrow^{*} C\), and \(B\) and \(C\) are normal forms, then \(B = C\).
\end{theorem}

\begin{proof}
  We proceed by induction on the common reduct of \(B\) and \(C\).

\begin{leancode}
theorem RedAffReflTrans.norm_unique (h₁ : RedAffReflTrans A B) (h_norm : B.IsNormAff)
  (h₂ : RedAffReflTrans A C) (h_norm₂ : C.IsNormAff) : B = C := by
  have ⟨D, ha, hb⟩ := h₁.conf h₂
  match ha.cases_head, hb.cases_head with
  | .inl h₁, .inl h₂ =>
    simp_all
  | .inr ⟨c₁, h₁, h₂⟩, _ =>
    exact h_norm.elim ⟨_, h₁⟩
  | _, .inr ⟨c₁, h₁, h₂⟩ =>
    exact h_norm₂.elim ⟨_, h₁⟩
\end{leancode}
\end{proof}

\subsection{Decidable Beta-Equality}

We give a decision procedure for \(=_{\beta}\). We do so by proving soundness and completeness for \(\beta\)-reduction (with respect to normal-forms). We thus implement an instance of:\\

\mintinline{lean}{∃ C, RedAffReflTrans A C ∧ RedAffReflTrans B C ∧ C.IsNormAff}\\

First, we define \texttt{step} and \texttt{reduce} functions with soundness using our measure:

\begin{leancode}
def step? (e : Expr) : Option ((e' : Expr) × (PLift (RedAff e e'))) :=
  match e with
  | (DCC (App(_n, _δ, _τ) ⟦_α, _β⟧(f, x)))  => .some ⟨(DCC (f x)), ⟨.app⟩⟩
  | (DCC (Fst(_δ, _τ) ⟦_α, _β⟧(a, _b)))     => .some ⟨a, ⟨.fst⟩⟩
  | (DCC (Snd(_δ, _τ) ⟦_α, _β⟧(_a, b)))     => .some ⟨b, ⟨.snd⟩⟩
  | (DCC (Snd'(_δ, _τ) ⟦_α, _β⟧(_a, b)))    => .some ⟨b, ⟨.snd'⟩⟩
  | (DCC (Flip(e) x y))                     => .some ⟨(DCC (e y x)), ⟨.flip⟩⟩
  | (DCC (Id(_α) x))                        => .some ⟨x, ⟨.id⟩⟩
  | (DCC (`(_α, _β, x) _y))                 => .some ⟨x, ⟨.quot⟩⟩
  | (DCC ((⟦_α, _β, _γ⟧∘ x y) z))           => .some ⟨(DCC (x (y z))), ⟨.comp⟩⟩
  | (DCC ((x ∘' y) z))                      => .some ⟨(DCC (x (y z))), ⟨.comp'⟩⟩
  | (DCC (Λ(α, x) y z))                     => .some ⟨(DCC (x ⟦α, Id(α)⟧(y, z))), ⟨.curr⟩⟩
  | (DCC (Λ'(α, β, x) y z))                 => .some ⟨(DCC (x ⟦α, β⟧(y, z))), ⟨.curr'⟩⟩
  | DCC (f x) =>
    match f.step?, x.step? with
    | .some ⟨f', ⟨h₁⟩⟩, _ => .some ⟨(DCC (f' x)), ⟨.congrFun h₁⟩⟩
    | _, .some ⟨x', ⟨h₁⟩⟩ => .some ⟨(DCC (f x')), ⟨.congrArg h₁⟩⟩
    | _, _ => .none
  | _ => .none

def reduce (e : Expr) : Expr :=
  match step? e with
  | .some ⟨e', ⟨h⟩⟩ =>
    have _h_size : e'.size.fst < e.size.fst := h.decreasing
    e'.reduce
  | .none => e
\end{leancode}

\begin{theorem}
  For all \(A \in Expr\), and \texttt{reduce A = B}, then \(A \dashrightarrow^{*} B\).
\end{theorem}

\begin{proof}
\begin{leancode}


theorem reduce_sound (heq : reduce A = B) : RedAffReflTrans A B := by
  induction A using instWellFounded.induction generalizing B with
  | h a ih =>
    unfold reduce at heq
    split at heq
    case h_1 h_red h_step_eq =>
      exact Relation.ReflTransGen.trans (.single h_red) (ih _ h_red heq)
    case h_2 => simp_all only [forall_eq']; exact .refl
\end{leancode}
\end{proof}

By using our decreasing measure and showing completeness for \mintinline{lean}{step?} with respect to normal forms under \(\dashrightarrow\), we prove completeness of \mintinline{lean}{reduce} with respect to normal forms under \(\dashrightarrow^{*}\).

\begin{lemma}
  For all \(e \in Expr\), if \(e\) is a normal form, then \texttt{step? e = none}.
\end{lemma}

\begin{proof}
\begin{leancode}


  theorem IsNormAff.complete (h : A.IsNormAff) : (step? A) = .none := by
  apply Option.eq_none_iff_forall_ne_some.mpr
  intro ⟨e', ⟨h₂⟩⟩ heq
  exact (h ⟨_, h₂⟩)
\end{leancode}
\end{proof}

\begin{theorem}
  For all \(A \in Expr\), if \(A \dashrightarrow B\) and \(B\) is a normal form, then \texttt{step A = some B}.
\end{theorem}

\begin{proof}
  We proceed by case analysis with respect to the unfolding of \mintinline{lean}{step?}:
\begin{leancode}
theorem RedAff.complete (h₁ : RedAff A B) (h_norm : B.IsNormAff) :
  (step? A) = .some ⟨B, ⟨h₁⟩⟩ := by
  unfold step?
  split
  case h_4 | h_3 | h_2 | h_1  =>
    cases heq : h₁
    · rfl
    · rename_i h_r
      have h := h_r.complete h_norm.congrFun
      simp [step?] at h
    · rename_i h_r
      cases h_r
      · rename_i h_r
        cases h_r
        · rename_i h; cases h
        · have h := h_norm.complete
          simp [step?] at h
      · have h := h_norm.complete
        simp [step?] at h
  case h_7 | h_6 =>
    cases heq : h₁
    · rfl
    · rename_i h; cases h
    · have h := h_norm.complete
    simp [step?] at h
  case h_5 | h_8 | h_9 | h_10 | h_11 | h_12 | h_13 =>
    sorry -- omitted for brevity. See appendix.
\end{leancode}
\end{proof}

\begin{lemma}
For all \(e \in Expr\), if \(e\) is a normal form, then \texttt{reduce e = e}.
\end{lemma}

\begin{proof}
\begin{leancode}


theorem IsNormAff.complete_reduce (h : A.IsNormAff) : reduce A = A := by
  unfold reduce
  rw [h.complete]
\end{leancode}
\end{proof}

\begin{theorem}
  For all \(A \in Expr\), if \(A \dashrightarrow^{*} B\), and \(B\) is a normal form, then \texttt{reduce A = B}.
\end{theorem}

\begin{proof}\label{decide_beta_eq}
  By well-founded recursion with respect to the decreasing measure \texttt{size}:
\begin{leancode}
theorem RedAffReflTrans.complete (h₁ : RedAffReflTrans A B) (h_norm : B.IsNormAff) :
  reduce A = B := by
  match h₁.cases_head with
  | .inl h =>
    simp_all
    exact h_norm.complete_reduce
  | .inr ⟨c, h₁, h₂⟩ =>
    have _h : sizeOf c < sizeOf A := h₁.decreasing
    have h := RedAffReflTrans.complete h₂ h_norm
    rw [h₁.reduce_same, h]
termination_by A.size.fst
\end{leancode}
\end{proof}

Finally, we show \(=_{\beta}\) is decidable.

\begin{theorem}
  For all \(A \in Expr\) and \(B \in Expr\), \((\exists C, A \dashrightarrow^{*} C \land B \dashrightarrow^{*} C \land IsNorm(C)) \lor \neg (\exists C, A \dashrightarrow^{*} C \land B \dashrightarrow^{*} C IsNorm(C))\).
\end{theorem}

\begin{proof}
  This follows from completeness and soundness of \texttt{reduce}:
\begin{leancode}
instance : Decidable (∃ C, RedAffReflTrans A C ∧ RedAffReflTrans B C ∧ C.IsNormAff) :=
  if heq : reduce A = reduce B then .isTrue
    ⟨_, reduce_sound rfl, reduce_sound heq.symm, reduce_norm rfl⟩
  else
    .isFalse (fun ⟨C, h₁, h₂, h_norm⟩ => by
      have ha := h₁.complete h_norm
      have hb := h₂.complete h_norm
      simp_all)
\end{leancode}
\end{proof}

\section{Decidable Type Inference}

Note that the types of all of the dependent categorical combinators are affine \eqref{infer_rules}. Hence, we use our decision procedure \eqref{decide_beta_eq} for \(=_{\beta}\) under affine-reduction to prove decidability of type-checking.

We do not normalize inside our judgment relation, nor do we have a conversion case. We bake conversion into each applicable constructor with a \texttt{Reduces} predicate by normalizing the expected and actual types a la carte:

\begin{leancode}
inductive Reduces : Expr → Expr → Type
  | mk : RedAffReflTrans A B → IsNormAff B → Reduces A B
deriving Repr

theorem Reduces.complete : Reduces A B → reduce A = B :=
  fun ⟨ha, hb⟩ => ha.complete hb

def reduce_reduces (h : reduce A = B) : Reduces A B := ⟨reduce_sound h, reduce_norm h⟩

def reduce_reduces' : Reduces A A.reduce := reduce_reduces rfl
\end{leancode}

For example, application is inferred like such:

\begin{leancode}
inductive Judge : Expr → Expr → Type where
  | app   : Judge f t_f
    → Reduces t_f (DCC (Π(m, n) α β))
    → Judge x t_x
    → Reduces t_x α
    → Judge (DCC (f x)) (DCC (β ⟦Sort m, Id(Sort m)⟧(α, x)))
\end{leancode}

We defer full type normalization to a supplementary predicate, \mintinline{lean}{JudgeConv}:

\begin{leancode}
inductive JudgeConv : Expr → Expr → Type
  | mk : Judge x A → Reduces A B → JudgeConv x B
\end{leancode}

We define an \mintinline{lean}{IsArrow} predicate for convenience in pattern matching arrows, which are by convention, \(\Pi\)-objects containing quotation in their codomain. We do not assume \(\Pi\)-extensionality.

\begin{leancode}
inductive IsArrow : Expr → (α β : Expr) → Level → Level → Type
  | mk    : Reduces A (arrow α β m n) → IsArrow A α β m n
deriving Repr

def is_arrow (t : Expr) : Option ((α β : Expr) × (m n : Level) × IsArrow t α β m n) :=
  match heq₀ : t.reduce with
  | DCC (Π(m, n) α `(Sort n₂, Σ(Sort m₂, Id(Sort m₃)), β)) =>
    if heq : m = m₂ ∧ m = m₃ ∧ n = n₂ then by
      have ⟨ha, hb, hc⟩ := heq
      rw [← ha, ← hb, ← hc] at heq₀
      refine .some ⟨α, β, m, n, ?_, ?_⟩
      · exact reduce_sound heq₀
      · exact reduce_norm heq₀
    else .none
  | _ => .none
\end{leancode}

Our \mintinline{lean}{Judge} relation models the inference rules \eqref{infer_rules}. We have the individual types and corresponding constructors for brevity, but give the constructor for tail-dependent Curry \eqref{tail_curry} and App \eqref{infer_app} as examples. See the appendix and supplementary materials for the full formalization.

\begin{leancode}
def curr.type (α γ : Expr) (m n : Level) : Expr :=
  (DCC (Π(m.succ, n) α ((Flip(Π(m, n)) (γ ∘'
  (Λ'(Sort m.succ, Id(Sort m.succ), Id(Σ(Sort m.succ, Id(Sort m.succ))))
    ⟦Sort m.succ, Id(Sort m.succ)⟧(α, Id(α))))) ∘' Snd'(Sort m.succ, α))))

def app_e.type (α β : Expr) (m n : Level) : Expr :=
  let t_f := DCC (Π(m, n) α β)
  let t_x := DCC `(Sort n, t_f, α)

  DCC (Π(max m n, n)
      Σ(t_f, t_x)
      ((Λ'(Sort m, Id(Sort m), β) α) ∘' (Snd(t_f, t_x) ∘ Snd'(Sort (max m n), Σ(t_f, t_x)))))

inductive Judge : Expr → Expr → Type where
  | curr  : Judge α t_α
    → Reduces t_α (DCC (Sort m.succ))
    → Judge x t_x
    → Reduces t_x (DCC (Π(m.succ, n) Σ(α, Id(α)) γ))
    → Judge (DCC Λ(α, x)) (curr.type α γ m n)
  | app_e : Judge α t_α
    → Reduces t_α (DCC Sort m)
    → Judge (DCC App(n, α, β)) (app_e.type α β m n)
  | app   : Judge f t_f
    → Reduces t_f (DCC (Π(m, n) α β))
    → Judge x t_x
    → Reduces t_x α
    → Judge (DCC (f x)) (DCC (β ⟦Sort m, Id(Sort m)⟧(α, x)))
  | sort  : Judge (DCC Sort m) (DCC Sort m.succ)
deriving Repr
\end{leancode}

Using our terminating affine \(\beta\)-reduction function and \mintinline{lean}{reduce_reduces}, we define an \mintinline{lean}{infer} function with soundness. We give only the cases described in our \mintinline{lean}{Judge} illustration, though the rest are available in supplementary materials. Pattern matching against our \mintinline{lean}{Judge} constructors is somewhat obtuse, primarily due to our design decision to avoid adding a conversion constructor and reducing the inferred types.

\begin{leancode}
def infer (e : Expr) : Option ((t : Expr) × (Judge e t)) :=
  match e with
  | DCC Sort m => .some ⟨DCC Sort m.succ, .sort⟩
  | DCC Λ'(α, β, x) =>
    match x.infer, β.infer with
    | .some ⟨t_x, h_t_x⟩, .some ⟨t_β, h_t_β⟩ =>
      match t_x.is_arrow, t_β.is_arrow with
      | .some ⟨DCC Σ(α₁, β₂), γ, mn, o, heq₁⟩, .some ⟨DCC α₂, DCC Sort n, m, n₂, heq₂⟩ =>
        if heq : mn = max m n ∧ β₂ = β ∧ n₂ = n.succ ∧ α₂ = α ∧ α₁ = α then
          have ⟨ha, hb, hc, hd, he⟩ := heq
          .some ⟨_, .curr' h_t_x (by rw [ha, hb, he] at heq₁; exact heq₁) h_t_β (by rw [hd, hc] at heq₂; exact heq₂)⟩
        else .none
      | _, _ => .none
    | _, _ => .none
  | DCC Λ(α, x) =>
    match heq₀ : α.infer, x.infer with
    | .some ⟨t_α, h_t_α⟩, .some ⟨t_x, h_t_x⟩ =>
      match heq₁ : t_α.reduce with
      | DCC Sort m + 1 =>
        match heq₃ : t_x.reduce with
        | (DCC (Π(m₂ + 1, n) Σ(α₁, Id(α₂)) γ₂)) =>
          if heq₂ : m₂ = m ∧ α₁ = α ∧ α = α₂ then
            have ⟨ha, hb, hc⟩ := heq₂
            .some ⟨_, Judge.curr
              h_t_α
              (reduce_reduces heq₁)
              h_t_x
              (ha ▸ hb ▸ hc ▸ (reduce_reduces heq₃))⟩
          else .none
        | _ => .none
      | _ => .none
    | _, _ => .none
  | DCC (f x) => match f.infer, x.infer with
    | .some ⟨t_f, h_f⟩, .some ⟨t_x, h_x⟩ =>
      match heq₀ : t_f.reduce, heq₁ : t_x.reduce with
      | DCC (Π(m, n) α₁ β), α₂ =>
        if heq : α₁ = α₂ then
          .some ⟨(DCC (β ⟦Sort m, Id(Sort m)⟧(α₁, x))), .app h_f (reduce_reduces heq₀) h_x (reduce_reduces (heq ▸ heq₁))⟩
        else .none
      | _, _ => .none
    | _, _ => .none
  | _ => sorry -- remaining cases omitted for brevity

def infer_conv (e : Expr) : Option ((t : Expr) × JudgeConv e t) :=
  match infer e with
  | .some ⟨t, h⟩ =>
    .some ⟨t.reduce, ⟨h, reduce_reduces rfl⟩⟩
  | _ => .none
\end{leancode}

Avoiding a conversion constructor proves to be quite advantageous, since neither confluence or induction are necessary, and case analysis suffices to prove useful properties. For example, a proof of preservation of \(Id(\alpha) x\) is quite straightforward.

\begin{theorem}
  For all \(\alpha \in Expr\) and \(x \in Expr\), if \(Id(\alpha) x : reduce(\alpha)\), then \(x : reduce(\alpha)\).
\end{theorem}

\begin{proof}
  We proceed by case analysis on the judgment \(Id(\alpha) x : reduce(\alpha)\).

\begin{leancode}
def id_preservation (h : JudgeConv (DCC (Id(α) x)) α.reduce) : (JudgeConv x α.reduce) :=
  match h with
  | ⟨.app (.id _ _) b h_t_x _, h_red⟩ => by
    cases reduce_arrow b.complete
    exact ⟨h_t_x, by assumption⟩
\end{leancode}
\end{proof}
